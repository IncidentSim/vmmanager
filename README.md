# vmmanager

Сервис для управления микровиртуальными машинами [Firecracker](https://firecracker-microvm.github.io/) на одном Linux-хосте.
Прежнее название проекта — vibe-firecracker.

## Что это делает

Типичный сценарий:

1. Создать VM из готового образа.
2. Зайти по SSH и настроить систему под себя.
3. Сохранить результат как новый образ.
4. Запускать из него новые, независимые друг от друга VM.

Работать можно через HTTP API, командную строку `vmctl` и Go-клиент; по желанию — через Telegram-бота
или браузер (веб-терминал).

## Как это устроено (в общих чертах)

- На хосте работает один сервис `vmapi`: он принимает запросы и сам управляет настоящими процессами Firecracker.
  Клиенты (CLI, Go-код, бот) только обращаются к его API.
- Сервис помнит свои данные и состояние VM и образов между запросами.
- У каждой VM есть владелец; задаются ограничения на число VM, CPU и память, а также срок жизни (TTL).
- Сохранение образа — «холодное»: диск записывается после штатной остановки VM. Это **не** снимок работающей
  памяти, запущенные процессы не сохраняются.
- Общий реестр образов: сохранённые образы видны другим разрешённым пользователям API. Не кладите в них секреты.

## Ограничения

- Нужны Linux с KVM и systemd, а хост должен подготовить администратор (Firecracker, ядро и образ гостя, хранилище,
  сеть). Это не «один бинарник, который работает сразу».
- Подходят только образы, которые проходят проверки проекта; произвольные образы не гарантируются.
- Это не защищённая многопользовательская среда: владение VM в API не делает хост границей безопасности между
  недоверяющими друг другу пользователями.
- Полное восстановление после любых сбоев не гарантируется.

## Быстрый старт

**[Локальный запуск с настоящим Firecracker → LOCAL-RUN.md](LOCAL-RUN.md)**

Пошаговое руководство: API на `127.0.0.1:8090` с реальным Firecracker. Публичный доступ, Telegram-бот и TLS
не нужны. Проверено на чистой Ubuntu 24.04 x86_64 с вложенным KVM (подробности и границы проверки — в руководстве).

## Сборка (для разработки)

```sh
make build   # собрать бинарники
make check   # проверки без запуска гостевых VM
```
